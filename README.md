# AI资金驾驶舱 · 重构版

面向建筑业的合同收支计划、确定性情景推演和付款约束安排。当前为浏览器本地数据版，不是银行交易系统；没有训练后的机器学习模型，不将规则分称为真实概率。

## 运行

在 frontend 目录执行 npm ci、npm test、npm run dev。生产构建：npm run build。
需要 Node.js 22+；本次验证使用 Node.js 24。
在线版由仓库根目录 vercel.json 构建 frontend/dist，api/ai 仅提供本地模式状态与明确的未配置响应。

## 页面与设计

### 项目优先版本（2026-09-29）

顶部主导航为项目与合同、公司收支预测、公司付款统筹、情景对比、账户与导入。
单项目预测从项目卡片进入；旧总览、独立风险评分、付款评分和重复现金流页面已移除，旧链接跳转到对应新入口。
每个预测页面明确显示公司或单项目范围、统一基准日、选定周期，并提供逐日核对、合同事件和结果说明。
项目内集中维护业主收款、预付款扣回、产值计划、分包付款、基准与垫资约束，并提供全生命周期收支预览。

- 进度比例按累计产值计算，竣工/结算/质保按合同额累计补差。例如80/90/97/100，不是各阶段金额相加。
- 预付款按合同额比例计提，填写历史已收/已扣，达到累计产值门槛当期起扣回。可选产值或进度款作为扣回基数，每次不超过剩余预付款及当期应收。
- 自动产值可选均匀或S形；也可逐月手工或CSV导入，剩余产值必须与合同额扣除期初产值一致。
- 详细分包按均匀产值与累计付款比例推算；简易分包按剩余估算额分月。两种模式均支持进场时间、账期、重要系数和资料完整状态。
- 项目存贷差是归属账，不重复增加公司银行余额。允许垫资期内不得低于负额度，窗口外不得为负。公司与各专户余额不得透支。
- 统筹权重为10000×项目系数×分包系数×(1+min(逾期天数,90)/30)，刚性义务单独给予高惩罚权重；并非严格词典序保证。优化仅检查选定周期，不能保证周期外偿还。
- 新的合同模式默认不启用，不改变既有数据。保存设置并启用后，保留该项目原始收付款备查，但计算仅用生成计划；停用可恢复原口径。计算固定使用项目基准日；公司合并要求所有启用项目基准日一致，不能将不同日期的期初直接相加。

### 下游成本与付款比例预警

项目内“成本确认与付款预警”按项目合并所有下游；实际比例为分包累计已付合计÷同日累计已确认成本，默认在施70%、竣工80%、结算后100%。每项目独立启停、调比例，无公司总开关。预警不修改分包合同、付款排序、质保金或优化约束。
成本按月填写累计数（元），区分已确认与未来计划；支持CSV模板按月份及类型合并导入、先校验后保存。基准日实付仅与同日已确认成本比较，成本缺失或0显示依据不足；未来仅在成本计划日期核对，不插值或外推，未覆盖期末明确提示。自动阶段日期独立于业主回款日期；手动阶段覆盖整个预测期。
已有4个命名模拟项目可在工作台一次补充成本：只填尚未配置的预警与成本字段，不覆盖其他数据，不重复覆盖。示例包含正常、超比例和零成本待确认。

### 其他模板导入

项目、账户在“账户与导入”下载中文CSV模板；重复的逐笔收付款录入入口已移除，历史原始数据仍保留在备份中；项目工作台内提供合同条款、逐月产值、分包计划模板。
Excel/WPS填写后保存为CSV UTF-8（当前不直接读取XLSX）。金额为元，比例填80而不是0.8，日期YYYY-MM-DD。
界面先校验并预览，确认后整批写入；错误不写入。编号留空新增，已有编号更新，未知编号和重复编号拒绝。分包按编号合并，产值显式替换；工作台导入先进入草稿，仍需保存。
本次没有实现业务API接入、跨设备同步或外部AI启用。

### 当前建模边界

期初欠收进度款由累计产值、未扣预付款及累计实收推导，按用户设置到账日生成；不是已确认到账。默认首日时必须人工核实。
本版最终结算基数为合同额，未单列变更签证、动态结算价、税款/总部管理费预测。
本地数据和账户余额须在同一基准日更新，系统不自动识别已发生银行流水。

- 项目预测：项目期初存贷差＋本项目收款－本项目分包应付；展示垫资峰值及超限日期。
- 公司预测：公司银行期初＋各项目本期收款－各项目本期应付，不重复加入项目存贷差。
- 公司付款统筹：混合整数规划、专户限制、付款窗口、权重、垫资额度及期限共同校验。
- 情景对比：逐条新增项目情况，各自设置晚收款、未来节点延迟、材料付款增幅；未添加项目不变。公司与单项目查看范围独立，可明确带入付款统筹（最多90天），不修改原合同。
- 新手路径：填项目合同 → 核对银行余额 → 看是否缺钱 → 安排付款。结果先给白话结论，再给原计划/情景对比；预留资金目标和真实资金缺口不重复相加。
- 结果说明随当前范围与周期生成；不再使用旧评分建议直接支付。

UI采用顶部导航、浅色透明玻璃表面、圆润卡片与表单。项目为首要入口，公司统筹为后续决策；保留响应式手机布局、系统中文字体和本地Inter数字字体。
参考：https://carbondesignsystem.com/data-visualization/dashboards/ 与 https://ant.design/docs/spec/data-display/

## 计算架构

frontend/src/domain/forecast.ts：显式公司/项目范围、基准日与期初校验、汇总核对。
frontend/src/domain/simulation.ts：纯函数事件生成与每日滚动。
frontend/src/domain/optimizer.ts：MILP模型，最多100笔到期申请，5秒求解上限，不承诺全局最优；展示前独立复核金额守恒与账户余额。
frontend/src/domain/optimizer.worker.ts：隔离求解，避免阻塞界面；15秒终止保护。
frontend/src/api/index.ts：本地存储、数据校验、兼容汇总、备份和规则报告。
frontend/src/components/Chart.tsx：按需注册图表组件，减少图表体积。

旧AI评分规则已移除；备份兼容字段置零，不参与付款或风险判断。收款金额按合同事件全额保留，不将概率乘以金额。未付义务全部纳入合同基准，不因评分低或资料缺失而消失。
一般资金、工资专户、项目专户分池；未分类资金和未绑定账户的回款不纳入可调度资金。
期末合计 = 期初合计 + 已分类账户收款 - 全部到期义务。一般资金负数表示未筹足需求，不是真实账户获准透支。
一般资金筹资需求 = max(0, -最低一般资金余额)。安全储备不足 = max(0, 安全储备目标 - 最低一般资金余额)。目标默认0，可自行设置；二者不可相加。
付款优化将安全线作为软约束，账户不透支及用途为硬约束；优先高权重刚性义务，但无钱或资料不全时会显示未覆盖，不伪造可支付方案。

## 假设与边界

- 初次访问为明确标记的虚构演示数据：3个账户、8个项目、12笔收款与12笔付款。
- 工期压力作用于合同生成的进度款、竣工款、结算款及旧记录中“未到节点”的回款，不移动期初欠收、预付款与质保金；旧记录独立设置的质保金不自动平移。该压力口径是统一延迟假设，不是施工网络工期计算。
- 材料压力增幅作用于所选项目所有未支付材料类义务；不代表对已签固定价合同的真实涨价判断。
- 日期已过但仍未到账的回款暂置首日并警告，必须由财务人员更新确认日期；不宜直接作为经营决策输入。
- 压力情景为用户假设，不是可信区间；垫资风险按所选区间校验，不将全周期剩余分包款直接判成近期风险。
- 没有跨设备同步、多人权限、真实审批、银行执行或模型训练。公开版不开放付费模型代理。
- 原 backend/、Dockerfile、render.yaml 作为旧版实现保留，不参与当前Vercel部署；其中算法不是本版计算依据。生产化应另行设计数据库、权限和审计。

## 数据迁移与安全

旧域名的本地数据不会自动跨域迁移。在旧站导出JSON备份，再在新站“数据管理 → 导入数据备份”中导入。
导入前会确认替换，校验失败不覆盖旧数据。损坏的存储也不会被示例数据静默覆盖。
未分类旧账户须指定资金用途；旧回款须指定收款账户。备份可能包含企业敏感信息，请自行安全保管。
个人录入数据只在当前浏览器，不提交GitHub、不上传服务器；浏览器清理仍会丢失，需定期备份。
.env、.env.local、.vercel 和本地测试输出均排除提交。仓库沿用原有可见性。
